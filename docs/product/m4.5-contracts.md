## 1. Architectural Foundation & Separation of Concerns

OwnHands M4.5 introduces a four-tier architecture that bridges human users and AI agents (Codex, Claude, Antigravity) to the deterministic verification engine (`devharness` Core).

```text
User / Agent (Codex, Claude, Antigravity)
      ↓
[Tier 1: Router Skill] `using-ownhands`
  - High-level intent classification
  - Task lifecycle and phase transition routing
  - Never directly performs deep inspections or command executions
      ↓
[Tier 2: Sub Skills] (4 Canonical Sub-Skills)
  - `context-validation`: Context hygiene, manifest inspection, applicability gate, benchmarks, and context guarantees
  - `harness-profiler`: Environment discovery, baseline interview, contract validation, and preview compilation
  - `execution-control`: Worktree sandboxing, restore capture, runtime controls check, task lifecycle, candidate apply/rollback
  - `test-assurance`: Baseline recording, test comparison, gap detection, test design memo, diff impact, regression gate, and task guarantees
      ↓
[Tier 3: MCP Tools Gateway] (`devharness.mcp.server.McpServer`)
  - Deterministic execution boundary via standard stdio JSON-RPC 2.0
  - 25 Frozen Canonical Tools with strict schemas and Option C response envelope
  - Zero arbitrary code generation by LLMs
      ↓
[Tier 4: Core Engine] (`devharness` stdlib-only)
  - SQLite Catalog (Schema v3), Append-only Event Log, CAS Evidence Store
  - Enforced sandboxing, Git restore verification, Regression Gate algorithms
  - Core 0-mutation: Existing M0~M4 signatures and databases remain intact
      ↓
[Outcome: Sealed Evidence & Actionable Decisions]
  - Immutable SHA-256 evidence records
  - Transparent 4-state decisions (`pass`, `soft_block`, `hard_block`, `unobserved`)
```

### 2.2 Standard 2-Tier Response Envelope
Every MCP tool execution returns a predictable, standardized envelope:

```json
{
  "status": "ok",
  "decision": "pass",
  "evidence_id": "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "data": {
    "summary": "...",
    "details": {}
  },
  "error": null
}
```

#### Envelope Fields:
1. `status` (`"ok"` | `"error"`):
   - `"ok"`: The tool executed without internal server crashes or schema validation failures.
   - `"error"`: The tool failed to execute (e.g., invalid JSON arguments, missing required paths, internal exception).
2. `decision` (`"pass"` | `"soft_block"` | `"hard_block"` | `"unobserved"` | `null`):
   - Only populated for evaluative/verification tools.
   - Informational or scanning tools (e.g., `harness.profile`) return `null`.
   - Strictly preserves 4-state decisions without flattening `unobserved` into `soft_block`.
3. `evidence_id` (`string` | `null`):
   - When `task_id` is supplied in the request, the tool automatically stores the verified payload in the CAS Evidence Store and returns the SHA-256 reference `sha256:...`.
   - In dry-run or inspection mode (no `task_id`), returns `null`.
4. `data` (`object`):
   - The tool-specific payload containing raw findings, comparison records, or profile structures.
5. `error` (`object` | `null`):
   - When `status == "error"`, contains `{"code": str, "message": str}`. Otherwise `null`.

## 3. Decision & Error Semantics

### 3.1 Execution Success vs. Validation Decision
A fundamental principle of OwnHands is that **tool execution success is completely separate from validation pass**:

| Situation | `status` | `decision` | Meaning |
| :--- | :---: | :---: | :--- |
| **Tool Crash / Invalid Input** | `"error"` | `null` | Tool could not complete its inspection (e.g. malformed JSON or path). |
| **Clean Check (No Issues)** | `"ok"` | `"pass"` | Inspection succeeded; no blocking defects found. |
| **Warning / Policy Deviation** | `"ok"` | `"soft_block"` | Completed successfully, but findings require review or override. |
| **Regression / Defect Detected** | `"ok"` | `"hard_block"` | Completed successfully, but a breaking regression or hard safety violation was proven. Cannot be overridden. |
| **Incomplete Visibility** | `"ok"` | `"unobserved"` | Completed inspection, but external effects, missing receipts, or unobserved checks prevent verification. |
| **Pure Inspection / Scan** | `"ok"` | `null` | Non-evaluative scanning tool (e.g., `harness.profile`). |

### 3.2 Precedence Order
When aggregating statuses or checks within evaluative tools, strict precedence is enforced:
`hard_block > soft_block > unobserved > pass`

- A single `fail`, `regression`, `forbidden`, or `contradicted` condition forces `hard_block`.
- Warning, advisory, incomparable, missing-before, or unchanged-failure statuses map to `soft_block`.
- Missing observations, unrun checks, or `not_evaluated` claims map to `unobserved`.
- `pass` is returned ONLY when ALL required evaluations pass with observed evidence.

### 3.3 Human Override Policy
- **Soft Block Override:** Permitted only when accompanied by an exact `contract_fingerprint`, a recognized `override_actor`, and an audit reason. The status transitions to `decision: "pass"` with `initial_decision: "soft_block"`.
- **Hard Block Override:** Strictly rejected by the Core gate evaluator.

## 4. Conditional Evidence Persistence

```text
Tool Request with `task_id`:
  Input: { "root": "...", "sources": [...], "task_id": "task-42" }
  Processing:
    1. Core function computes inspection result
    2. EvidenceStore.record(draft, payload) saves CAS blob to disk
    3. SQLite catalog registers the event and evidence lineage
    4. Envelope returns `evidence_id: "sha256:..."`

Tool Request without `task_id` (Dry-run / Inspection):
  Input: { "root": "...", "sources": [...] }
  Processing:
    1. Core function computes inspection result
    2. Zero disk writes to EvidenceStore / SQLite catalog
    3. Envelope returns `evidence_id: null`
```

## 5. Domain Tool Specifications (25 Canonical Tools)

### 5.1 Context Domain (`context-validation` Sub-Skill)

1. **`context.lint`**
   - **Backing:** `devharness.context_architecture.lint_context(root, sources)`
   - **Input:** `root` (str), `sources` (list[dict]), optional `task_id` (str)
   - **Decision:** `"pass"` if findings empty; `"hard_block"` if hard rule violations; `"soft_block"` if advisory findings.

2. **`context.inspect`**
   - **Backing:** `devharness.context_architecture.validate_manifest(manifest, evidence_ids, event_ids)`
   - **Input:** `manifest` (dict), optional `evidence_ids` (list[str]), optional `event_ids` (list[str]), optional `task_id` (str)
   - **Description:** Validates context manifest structure and authoritative referential integrity against catalog evidence and event logs.
   - **Decision:** `"pass"` if manifest is valid; `"hard_block"` if manifest fails structural or referential validation.

3. **`context.gate_evaluate`**
   - **Backing:** `devharness.context_architecture.ApplicabilityGate.evaluate(gate_input)`
   - **Input:** `gate_input` (dict), optional `task_id` (str)
   - **Decision:** `"hard_block"` on `forbidden`; `"soft_block"` on `replace_with_specific`; `"unobserved"` on `unobserved`; `"pass"` if all clear.

4. **`context.benchmark_plan`**
   - **Backing:** `devharness.context_architecture.build_comparison_plan(package, target_commit)`
   - **Input:** `package` (dict), `target_commit` (str), optional `task_id` (str)
   - **Decision:** `"pass"` on successful generation of combinatorial comparison plan.

5. **`context.benchmark_evaluate`**
   - **Backing:** `devharness.context_architecture.evaluate_comparison(package, runs)`
   - **Input:** `package` (dict), `runs` (list[dict]), optional `task_id` (str)
   - **Decision:** `"pass"` on `recommended`; `"soft_block"` on `no_improvement`; `"unobserved"` on `not_evaluated`.

6. **`context.guarantee_evaluate`**
   - **Backing:** `devharness.context_architecture.evaluate_context_guarantees(matrix, manifest, evidence_records)`
   - **Input:** `matrix` (dict), `manifest` (dict), `evidence_records` (list[dict]), optional `task_id` (str)
   - **Decision:** `"hard_block"` on `contradicted`; `"unobserved"` on `not_evaluated`; `"pass"` if all `supported`.

### 5.2 Harness Profiler Domain (`harness-profiler` Sub-Skill)

7. **`harness.profile`**
   - **Backing:** `devharness.control_profile.profile_project(root, identity, observed_at=now)`
   - **Input:** `root` (str), optional `project_id`, `worktree_id`, `environment_ref`, `task_id`
   - **Decision:** `null` (informational scanning tool).

8. **`harness.contract_validate`**
   - **Backing:** `build_baseline(...)` via interview responses OR `build_execution_contract(...)` via baseline + overlay.
   - **Input:** (`profile` + `interview_responses`) OR (`baseline` + `overlay`, optional `approvals`), optional `task_id`
   - **Description:** Strictly rejects shallow direct contract inputs. Authoritatively compiles and validates baseline profiles and execution contracts.
   - **Decision:** `"pass"` if execution contract gate is clear and permissions active; `"hard_block"` on unapproved permissions or hard contract violations; `"soft_block"` on unresolved interview decisions.

9. **`harness.compile_preview`**
   - **Backing:** `devharness.control_profile.compile_control_profile(contract, existing)` and `render_control_preview(contract, compiled, evidence_index)`
   - **Input:** `contract` (dict), `existing` (dict[str, str]), optional `evidence_index` (dict), optional `task_id`
   - **Description:** Compiles control profile artifacts and generates standalone review HTML preview. Strictly consumes exact Core contracts without synthesizing artificial defaults.
   - **Decision:** `"hard_block"` if `compiled.apply_ready == False` or hard findings exist; `"pass"` otherwise.

### 5.3 Execution Control Domain (`execution-control` Sub-Skill)

10. **`sandbox.inspect`**
    - **Backing:** Adapter inspection of workspace git status, sensitive files, and command execution risks.
    - **Input:** `root` (str), optional `command` (str), optional `task_id` (str)
    - **Decision:** `"pass"` if safe; `"soft_block"` on elevated commands (e.g. sudo, package install); `"hard_block"` on destructive commands (e.g. rm -rf /).

11. **`git.restore_capture`**
    - **Backing:** `devharness.assurance.capture_restore_point(root, identity, observed_at=now)` and `devharness.assurance.verify_restore_point(root, restore_point)`
    - **Input:** `root` (str), optional `project_id`, `worktree_id`, `environment_ref`, `task_id`
    - **Description:** Captures clean worktree restore point and strips binary blob internals from public envelope data.
    - **Decision:** `"pass"` on verified capture.

12. **`runtime.controls_check`**
    - **Backing:** `devharness.control_runtime.evaluate_runtime_controls(prepared, run)`
    - **Input:** `prepared` (dict), `run` (dict), optional `task_id`
    - **Decision:** `"hard_block"` if any control check fails; `"pass"` ONLY when all required controls have all required checks as observed pass; `"unobserved"` if any required check is not_run or unobserved.

13. **`task.prepare`**
    - **Backing:** `devharness.managed_tasks.prepare_managed_task(arguments, now=now)`
    - **Input:** `task_id`, `repository`, `patch_hash` (exact sha256: 71-char), `predecessor_patch_hash`, etc.
    - **Decision:** `"pass"` on valid preparation.

14. **`task.create`**
    - **Backing:** `devharness.identity.IdentityRegistry.create_task_lifecycle(project_locator, worktree_locator, mode, commit, branch, cwd, environment_ref, task_id=None)`
    - **Input:** `project_locator` (str), `worktree_locator` (str), `mode` (str), `commit` (str), `branch` (str), `cwd` (str), `environment_ref` (str), optional `task_id` (str)
    - **Description:** Atomic Core lifecycle mutation provisioning Project, Worktree, Task, and canonical `task.created` Event with rollback on failure.
    - **Decision:** `"pass"` on successful atomic creation.

15. **`task.record_run`**
    - **Backing:** `devharness.managed_tasks.record_managed_run(catalog, prepared, run)`
    - **Input:** `prepared` (dict), `run` (dict), optional `task_id`
    - **Decision:** `"pass"` on successful recording of managed execution.

16. **`task.import`**
    - **Backing:** `devharness.imported_tasks.import_task(fixture, catalog)`
    - **Input:** `fixture` (dict), optional `task_id`
    - **Decision:** `"pass"` on successful import into SQLite catalog.

17. **`harness.candidate_apply`**
    - **Backing:** `devharness.control_profile.apply_candidate(compiled, root, approval)`
    - **Input:** `compiled` (dict), `root` (str), `approval` (dict), optional `task_id`
    - **Decision:** `"pass"` on verified apply.

18. **`harness.candidate_rollback`**
    - **Backing:** `devharness.control_profile.rollback_candidate(root, journal_path)`
    - **Input:** `root` (str), `journal_path` (str), optional `task_id`
    - **Decision:** `"pass"` on verified rollback.

### 5.4 Test Assurance Domain (`test-assurance` Sub-Skill)

19. **`tests.baseline_record`**
    - **Backing:** `devharness.assurance.record_test_baseline(contract, selection, receipts, observed_at)`
    - **Input:** `contract` (dict), `selection` (list[dict]), `receipts` (list[dict]), `observed_at` (str), optional `task_id`
    - **Decision:** `"pass"` if test run receipts recorded; failing tests are valid TDD baselines and return `"pass"`.

20. **`tests.compare_runs`**
    - **Backing:** `devharness.assurance.compare_test_runs(before, after)`
    - **Input:** `before` (dict), `after` (dict), optional `task_id`
    - **Decision:**
      - `"hard_block"` if `regression` or `contradicted` exists;
      - `"soft_block"` if `stale`, `incomparable`, `missing_after`, `unchanged_failure`, or `inconclusive` exists;
      - `"unobserved"` if `missing_before` or `not_run` exists or comparisons empty;
      - `"pass"` ONLY if all comparisons are `comparable_pass` or `fixed_failure`.

21. **`tests.gap_detect`**
    - **Backing:** `devharness.assurance.detect_test_gaps(contract, impact, design, comparison)`
    - **Input:** `contract` (dict), `impact` (dict), `design` (dict), `comparison` (dict), optional `task_id`
    - **Decision:** Evaluates Core `gaps` list: `"hard_block"` if critical gaps; `"soft_block"` if non-critical gaps; `"pass"` if gaps empty.

22. **`tests.design_memo`**
    - **Backing:** `devharness.assurance.build_test_design(contract, impact, requirement_catalog)`
    - **Input:** `contract` (dict), `impact` (dict), `requirement_catalog` (list[dict]), optional `task_id`
    - **Decision:** Evaluates `omitted_viewpoints`: `"soft_block"` if viewpoints omitted; `"pass"` if all covered.

23. **`git.diff_impact`**
    - **Backing:** `devharness.assurance.analyze_impact(repository, restore_point, contract, relation_catalog, observed_at)`
    - **Input:** `root` (str), `contract` (dict), `restore_point` (dict), `relation_catalog` (dict), optional `task_id`
    - **Decision:** `"hard_block"` on `protected_target_changes`; `"soft_block"` on `unobserved`; `"pass"` if clean.

24. **`assurance.gate_evaluate`**
    - **Backing:** `devharness.assurance.evaluate_regression_gate(contract, impact, design, comparison, gaps, override=None)`
    - **Input:** `contract` (dict), `impact` (dict), `design` (dict), `comparison` (dict), `gaps` (dict), optional `override` (dict), optional `task_id`
    - **Decision:** Authoritative calculation of `"pass"`, `"soft_block"`, or `"hard_block"`. Hard blocks strictly reject human override.

25. **`guarantee.evaluate`**
    - **Backing:** `devharness.guarantees.GuaranteeEvaluator.evaluate(task_id, claim_ids=None)`
    - **Input:** `task_id` (str), optional `matrix_path` (str), optional `claim_ids` (list[str])
    - **Decision:** Evaluates Task Guarantee Report: `"hard_block"` on `contradicted`; `"unobserved"` on `not_evaluated`; `"pass"` if all claims `supported`.

## 6. Core 0-Mutation Invariant & Additive Lifecycle Amendment

1. No existing function signatures in `src/devharness/` may be destructively altered to accommodate MCP needs.
2. The MCP gateway acts solely as an external adapter wrapping Core functions with JSON validation and canonical response envelopes.
3. All existing unit and integration tests must remain 100% green without regression.
4. **Additive Core Amendment (M4.5):** To guarantee atomic failure consistency when provisioning tasks (Project → Worktree → Task → canonical `task.created` Event), `IdentityRegistry.create_task_lifecycle()` was added as a non-breaking additive Core API, formally elevating end-to-end task lifecycle consistency into Core domain responsibility.
