- **Status:** Accepted (Option C — Hybrid Contract)

- **Target Audience:** Skill authors, MCP Tool implementers, Core runtime maintainers

## 1. Architectural Foundation & Separation of Concerns

OwnHands M4.5 introduces a four-tier architecture that bridges human users and AI agents (Codex, Claude, Antigravity) to the deterministic verification engine (`devharness` Core).

```text
User / Agent (Codex, Claude, Antigravity)
      ↓
[Tier 1: Router Skill] `using-ownhands`
  - High-level intent classification
  - Task lifecycle and phase transition routing
  - Never directly performs deep inspections or command executions
      ↓
[Tier 2: Sub Skills] (`context-validation`, `test-design`, `harness-profiler`, etc.)
  - Methodological judgment & heuristics (e.g., ISTQB CTFL test design)
  - Determines *what* to inspect and *when* to block or proceed
  - Decides which deterministic MCP tools to invoke
      ↓
[Tier 3: MCP Tools Gateway] (`ownhands-mcp-server`)
  - Deterministic execution boundary via standard stdio JSON-RPC 2.0
  - Zero arbitrary code generation by LLMs
  - Strict input validation and Option C response packaging
      ↓
[Tier 4: Core Engine] (`devharness` stdlib-only)
  - SQLite Catalog (Schema v3), Append-only Event Log, CAS Evidence Store
  - Enforced sandboxing, Git restore verification, Regression Gate algorithms
  - Core 0-mutation: Existing M0~M4 signatures and databases remain intact
      ↓
[Outcome: Sealed Evidence & Actionable Decisions]
  - Immutable SHA-256 evidence records
  - Transparent 4-state decisions (`pass`, `soft_block`, `hard_block`, `unobserved`)
```

## 2. Option C Protocol Principles

### 2.1 Naming Convention: `domain.action`
All tools exposed by the OwnHands MCP server follow a two-part dot-separated namespace:
- `context.lint`, `context.inspect`
- `harness.profile`, `harness.contract_validate`, `harness.compile_preview`
- `sandbox.inspect`, `approval.inspect`, `runtime.controls_check`
- `git.restore_capture`, `git.diff_impact`
- `tests.design_memo`, `tests.compare_runs`, `tests.gap_detect`
- `assurance.gate_evaluate`
- `evidence.record`, `guarantee.evaluate`

### 2.2 Standard 2-Tier Response Envelope
Every MCP tool execution returns a predictable, standardized envelope:

```json
{
  "status": "ok",
  "decision": "pass",
  "evidence_id": "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "data": {
    "summary": "...",
    "details": {}
  },
  "error": null
}
```

#### Envelope Fields:
1. `status` (`"ok"` | `"error"`):
   - `"ok"`: The tool executed without internal server crashes or protocol transport failures.
   - `"error"`: The tool failed to execute (e.g., invalid JSON input, missing directory, internal exception).
2. `decision` (`"pass"` | `"soft_block"` | `"hard_block"` | `"unobserved"` | `null`):
   - Only populated for evaluative/verification tools.
   - Informational or scanning tools (e.g., `harness.profile`) return `null`.
3. `evidence_id` (`string` | `null`):
   - When `task_id` is supplied in the request, the tool automatically stores the verified payload in the CAS Evidence Store and returns the SHA-256 reference `sha256:...`.
   - In dry-run or inspection mode (no `task_id`), returns `null`.
4. `data` (`object`):
   - The tool-specific payload containing raw findings, comparison records, or profile structures.
5. `error` (`object` | `null`):
   - When `status == "error"`, contains `{"type": str, "message": str, "details": object}`. Otherwise `null`.

## 3. Decision & Error Semantics

### 3.1 Execution Success vs. Validation Decision
A fundamental principle of OwnHands is that **tool execution success is completely separate from validation pass**:

| Situation | `status` | `decision` | Meaning |
| :--- | :---: | :---: | :--- |
| **Tool Crash / Invalid Input** | `"error"` | `null` | Tool could not complete its inspection (e.g. malformed path). |
| **Clean Check (No Issues)** | `"ok"` | `"pass"` | Inspection succeeded; no blocking defects found. |
| **Warning / Policy Deviation** | `"ok"` | `"soft_block"` | Completed successfully, but findings require review. Can be overridden with explicit human approval and recorded rationale. |
| **Regression / Defect Detected** | `"ok"` | `"hard_block"` | Completed successfully, but a breaking regression or hard safety violation was proven. Cannot be overridden. |
| **Incomplete Visibility** | `"ok"` | `"unobserved"` | Completed inspection, but external effects, symlinks, or missing dependencies cannot be observed. |
| **Pure Inspection / Scan** | `"ok"` | `null` | Non-evaluative tool (e.g., `harness.profile`, `context.inspect`). |

### 3.2 Human Override Policy
- **Soft Block Override:** Permitted only when accompanied by an exact `contract_fingerprint`, a recognized `override_actor`, and an audit reason. The status transitions to `decision: "pass"` with `initial_decision: "soft_block"`.
- **Hard Block Override:** Strictly rejected by the Core gate evaluator.

## 4. Conditional Evidence Persistence

```text
Tool Request with `task_id`:
  Input: { "root": "...", "sources": [...], "task_id": "task-42" }
  Processing:
    1. Core function computes inspection result
    2. EvidenceStore.record(draft, payload) saves CAS blob to disk
    3. SQLite catalog registers the event and evidence lineage
    4. Envelope returns `evidence_id: "sha256:..."`

Tool Request without `task_id` (Dry-run / Inspection):
  Input: { "root": "...", "sources": [...] }
  Processing:
    1. Core function computes inspection result
    2. Zero disk writes to EvidenceStore / SQLite catalog
    3. Envelope returns `evidence_id: null`
```

## 5. Domain Tool Specifications

### 5.1 Context Domain (`src/devharness/context_architecture.py`)

#### 1. `context.lint`
- **Purpose:** Deterministic static lint of instruction sources (`AGENTS.md`, rules, overlays) against 12+ hygiene rules (broad universal wording, stale symbols, missing sources, shadow skills).
- **Core Function:** `devharness.context_architecture.lint_context(root, sources)`
- **Input Schema:**
  ```json
  {
    "type": "object",
    "required": ["root", "sources"],
    "properties": {
      "root": { "type": "string", "description": "Absolute path to project root" },
      "sources": {
        "type": "array",
        "items": {
          "type": "object",
          "required": ["source_id", "path", "source_type"],
          "properties": {
            "source_id": { "type": "string" },
            "path": { "type": "string" },
            "source_type": { "enum": ["agents_instruction", "instruction_overlay", "project_context", "reference", "skill", "task_instruction"] },
            "command_refs": { "type": "array", "items": { "type": "string" } },
            "skill_refs": { "type": "array", "items": { "type": "string" } },
            "code_refs": {
              "type": "array",
              "items": {
                "type": "object",
                "required": ["path", "symbol"],
                "properties": { "path": { "type": "string" }, "symbol": { "type": "string" } }
              }
            }
          }
        }
      },
      "task_id": { "type": "string", "description": "Optional task ID to bind and record evidence" }
    }
  }
  ```
- **Output `data` Schema:**
  ```json
  {
    "findings": [
      {
        "rule_id": "broad_universal_wording",
        "evidence": "always",
        "location": "AGENTS.md:14",
        "impact": "guidance may apply beyond intended scope",
        "suggestion": "state the exact task, phase, or boundary"
      }
    ],
    "unobserved": []
  }
  ```
- **Decision Logic:**
  - `findings` is empty ➔ `"pass"`
  - `findings` contains only advisory issues ➔ `"soft_block"`
  - `findings` contains critical missing sources ➔ `"hard_block"`

---

#### 2. `context.inspect`
- **Purpose:** Scans the active workspace to detect present context and rule files without modifying them.
- **Core Function:** File discovery joining `root` with `AGENTS.md`, `.codex/rules/*.rules`.
- **Input Schema:** `{"root": {"type": "string"}}`
- **Output `data` Schema:** List of detected source files, types, and SHA-256 digests. `decision: null`.

---

### 5.2 Harness Profiler Domain (`src/devharness/control_profile.py`)

#### 1. `harness.profile`
- **Purpose:** Automatically scans workspace project structure, build/test commands in `pyproject.toml`, Codex configuration layers, rules, hooks, and sensitive credentials paths.
- **Core Function:** `devharness.control_profile.profile_project(root, identity, observed_at=now)`
- **Input Schema:**
  ```json
  {
    "type": "object",
    "required": ["root"],
    "properties": {
      "root": { "type": "string" },
      "project_id": { "type": "string", "default": "default-project" },
      "worktree_id": { "type": "string", "default": "main" },
      "environment_ref": { "type": "string", "default": "local-env" }
    }
  }
  ```
- **Output `data` Schema:**
  `{"profile_id": str, "structure": [str], "sources": [...], "commands": [...], "sensitive_paths": [...], "unobserved": [...]}`. `decision: null`.

---

#### 2. `harness.contract_validate`
- **Purpose:** Validates the semantic integrity of a Task Execution Contract before execution.
- **Core Function:** `devharness.control_profile.build_execution_contract` / validation helpers.
- **Decision:** `"pass"` if contract satisfies all permission boundaries, `"hard_block"` if permission boundary is breached.

---

### 5.3 Assurance & Testing Domain (`src/devharness/assurance.py`)

#### 1. `git.diff_impact`
- **Purpose:** Analyzes actual Git tracked diff against declared relations (feature, contract, dependency, test) to compute impacted areas and unobserved boundaries.
- **Core Function:** `devharness.assurance.analyze_impact(repository, contract, relation_catalog)`
- **Decision:** `"pass"` if all changed paths map to declared relations, `"soft_block"` if unobserved relations exist.

---

#### 2. `tests.compare_runs`
- **Purpose:** Compares pre-change test baseline receipts with post-change receipts across identical commands, environment fingerprints, and contract signatures.
- **Core Function:** `devharness.assurance.compare_test_runs(before, after)`
- **Decision Logic:**
  - Has `"regression"` ➔ `"hard_block"`
  - Has `"stale"` | `"incomparable"` | `"missing_after"` ➔ `"soft_block"`
  - All tests `"comparable_pass"` or `"fixed_failure"` ➔ `"pass"`

---

#### 3. `assurance.gate_evaluate`
- **Purpose:** Authoritative evaluation of the final regression gate combining contract, impact, test design, comparisons, gaps, and optional human override.
- **Core Function:** `devharness.assurance.evaluate_regression_gate(contract, impact, design, comparison, gaps, override=None)`
- **Decision Logic:** Authoritative calculation of `pass`, `soft_block`, or `hard_block`. Hard blocks reject any override attempt.

---

### 5.4 Evidence Domain (`src/devharness/evidence.py`, `guarantees.py`)

#### 1. `evidence.record`
- **Purpose:** Explicitly stores an arbitrary verifiable payload into the CAS Evidence Store.
- **Core Function:** `devharness.evidence.EvidenceStore.record(draft, payload)`
- **Output:** `{"evidence_id": "sha256:...", "stored_at": "..."}`.

#### 2. `guarantee.evaluate`
- **Purpose:** Evaluates task evidence records against Guarantee Matrix v1.0 and generates the machine-readable Task Guarantee Report.
- **Core Function:** `devharness.guarantees.GuaranteeEvaluator.evaluate_task(...)`
- **Decision:** `"pass"` if all claims satisfied, `"soft_block"` if inconclusive/unobserved claims exist.

## 6. Core 0-Mutation Invariant

1. No existing function signatures in `src/devharness/` may be altered to accommodate MCP needs.
2. The MCP gateway acts solely as an external adapter wrapping Core functions with JSON validation and canonical response envelopes.
3. All 242 existing unit and integration tests must remain 100% green without modification.
