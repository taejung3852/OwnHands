# M1.5 Context Architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Define and pressure-test the reviewable context architecture for ownhands issues #16–#21 without implementing the M2 compiler or changing any live Codex configuration.

**Architecture:** A proposed ADR and placement policy define the human contract. One strict Task Harness Manifest keeps context and deterministic controls in separate arrays and models applicability, realization, and evidence basis independently. A small Python 3.12 standard-library probe validates semantic constraints, emits deterministic lint and applicability records, validates guarantee/report contracts, and prepares a fixed nine-run A/B/C comparison without invoking Codex during implementation.

**Tech Stack:** Python 3.12 standard library, `unittest`, JSON Schema draft 2020-12, Markdown

**Spec:** GitHub issues #16–#21 and `docs/product/향후계획.md`

## Global Constraints

- Keep the Python import namespace `devharness`; use `ownhands` as the product name in new product-facing artifacts.
- Keep `context_sources` separate from `control_sources` and `instruction_overlay` separate from `control_overlay`.
- Model applicability, realization (`configured`, `loaded`, `enforced`), and evidence basis (`observed`, `inferred`, `unobserved`) independently.
- Do not implement a Production Compiler, runtime integration, global configuration change, Production UI, or plugin vendoring.
- Do not invoke the nine Codex comparison runs during implementation.
- Use only the Python standard library in repository runtime code.
- Do not commit or accept the proposed ADR.
