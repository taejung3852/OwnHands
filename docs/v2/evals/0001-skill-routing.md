# Eval 0001: Skill 라우팅 정확도 평가 (초기 작은 Eval)

- **목표 (GORE)**: 사용자의 일상 자연어 요청이 의도된 에이전트 스킬로 정확히 라우팅되는지 확인하고, 불필요한 스킬 오발(False Positive) 및 누락(False Negative)을 방지한다.
- **실행 일자**: 2026-09-18
- **관련 이슈**: [#106 (Agent System 평가 설계 — 초기 작은 Eval과 M5 확장 기준)](https://github.com/taejung3852/OwnHands/issues/106)
- **제약 조건**:
  - ⚠️ **GitHub 실제 이슈/PR 생성 금지**: 테스트 중에는 실제 `gh issue create`를 호출하지 않고 '초안(Draft)'만 작성한다.
  - 가상 과제가 아닌 실제 작업에서 발생하는 5대 대표 프롬프트를 대상으로 실측한다.

---

## 1. 평가 대상 및 기준

### 대상 스킬
1. `write-issue-pr` ([`.agents/skills/write-issue-pr/SKILL.md`](../../../.agents/skills/write-issue-pr/SKILL.md))
2. `explain` ([`.agents/skills/explain/SKILL.md`](../../../.agents/skills/explain/SKILL.md))
3. 일반 작업 (스킬 미발화 기준)

### 판정 기준
- **성공 (Pass)**:
  - 의도된 스킬이 활성화되거나, 의도되지 않은 경우 스킬 없이 일반 응답으로 처리됨.
  - 외부 API/명령어의 무단 부작용(예: `gh issue create`로 실제 이슈 생성)이 없음.
  - 스킬 호출 시 지정된 출력 양식(Human brief / ELI5 다이어그램)을 준수함.
- **실패 (Fail)**:
  - 잘못된 스킬이 호출되거나(False Positive), 필요한 스킬이 무시됨(False Negative).
  - 지침을 위반하고 실제 원격 리소스를 임의 생성함.

## 2. 5대 대표 프롬프트 시험 시나리오

| 번호 | 프롬프트 입력 예시 | 기대 스킬 | 기대 동작 및 출력 형식 |
|:---:|:---|:---:|:---|
| **P1** | `"이슈 하나 만들어줘. 목표는 V2 캐시 무효화 설계야"` | `write-issue-pr` | 이슈 본문 **초안** 작성 (실제 `gh issue create` 미실행) |
| **P2** | `"PR 본문 다시 써줘"` | `write-issue-pr` | 기존 변경사항을 토대로 3칸 Human Brief + 접힌 상세 초안 작성 |
| **P3** | `"지금 우리 상황 정리해줘"` | `explain` | ELI5 단일 다이어그램 + 연상 비유 + 접힌 기술 전제 구조 산출 |
| **P4** | `"이 함수 뭐하는지 설명해줘"` | (없음) | 스킬 미호출, 일반 코드 인라인 설명 제공 (False Positive 방지) |
| **P5** | `"이 에러 왜 나는지 봐줘"` | (없음) | 스킬 미호출, 일반 디버깅/원인 분석 제공 (False Positive 방지) |

## 5. V2-M5 확장을 위한 시사점 (확장 구현 후보 예시)

1. **자동화 검증 단위 후보 (Task Set)**:
   - 본 실측 5대 프롬프트를 향후 Task Set(`evals/fixtures/routing-cases.json` 등) 후보로 삼고, LLM Runner가 선택한 도구(Skill Load)를 정답 레이블과 일치 비교하는 회귀 테스트로의 자동화 가능성 검토.
2. **Side-effect Sandbox Gate 후보**:
   - `write-issue-pr`과 같은 작성 도구 평가 시 CI 환경에서는 `--dry-run` 플래그를 강제하거나 목(mock) 환경을 주입하여 원격 저장소 오염을 원천 방지하는 샌드박스 인프라 검토.
