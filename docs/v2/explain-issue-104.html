Q1. Verifier에게 read-only 샌드박스를 부여한 핵심 목적은? 정답 확인
💡 구현자의 편향을 배제하고, 검증 과정 중 코드를 임의로 수정(mutation)하지 못하게 불변성을 강제하기 위함입니다.
Q2. explain·이슈 작성을 서브에이전트로 떼어내지 않은 이유는? 정답 확인
💡 세션 대화 맥락(이력)을 자식에게 프롬프트로 직렬화해 넘기는 핸드오프 비용이 모델 분리 이득보다 훨씬 크기 때문입니다.
엔지니어링 세부사항: 생략된 기술 전제와 미확인 Gap
  • 생략된 전제: 각 에이전트는 .codex/agents/*.toml에 정의되며, verifier와 reviewer는 sandbox_mode = "read-only"로 설정되어 있습니다.
  • 전문가의 예외 지적: Codex 공식 사양상 부모 세션의 라이브 권한(--yolo 등)이 자식의 read-only를 무효화할 수 있으므로, 하드 보안 강제가 아닌 '소프트 경계'로 취급합니다.
  • 미확인 사양: 부모의 전체 대화 히스토리가 자식 서브에이전트에게 자동 상속되지 않으므로, 호출 시 프롬프트에 명확한 수용 기준을 직렬화해야 합니다.
