3. Codex 내장 3종 vs 출발점
내장 역할 공식 사양 (원문) OwnHands V2 관계
default General-purpose fallback 메인 작업 턴
worker Execution-focused for implementation 구현/수정 위임 가능
explorer Read-heavy codebase exploration 조회 위임 가능 (단, read-only 아님)
💡 출발점은 0이 아님: "내장 3종으로 충분한가, 아니면 Verifier/Reviewer 커스텀 역할이 필요한가"가 핵심 질문.

결정 5
skills.config
현재 스킬 2개(write-issue-pr, explain) 중 역할별 ON/OFF 지정 여부
선택지 A: 최소 출발안 (내장 우선)
커스텀 agent TOML 없이 내장 default + explorer + worker로 시작. 검증/리뷰는 프롬프트 지침으로 처리 후 Eval에서 실패 관측 시 커스텀 추가.
선택지 B: 역할 1종 추가안 (Verifier 전용)
부모 맥락 오염을 차단하기 위해 .codex/agents/verifier.toml 1개만 신설. sandbox_mode = "read-only"로 독립 수용성 검수 전담.
📌 근거 자료, 공식 사양 vs 미확인(Gap), 제외 범위 펼치기
공식 문서 사양 (확인된 사실)
  • 정의 위치: ~/.codex/agents/*.toml (개인) 또는 .codex/agents/*.toml (프로젝트 REPO)
  • 필수 필드 (3개뿐): name, description, developer_instructions
  • 상속 규칙: Subagent는 부모의 sandbox 정책 및 composer 권한을 상속받음. 부모 턴의 라이브 override(예: --yolo)가 파일 설정보다 우선 재적용됨.
  • 도구 제한 단위: skills.config는 path와 enabled 둘뿐. references/ 파일 단위 제어 키는 존재하지 않음.
⚠️ 공식 문서가 말하지 않는 것 (Gaps & Unverified)
  • 컨텍스트 전달 범위: 부모 대화 이력/트랜스크립트 중 무엇을 자식이 보는지 공식 문서에 서술 없음 (llms-full.txt 전량 확인). → 대책: 프롬프트로 명시적 전달 필요.
  • 중첩 위임(Nested Delegation): Subagent가 다시 Subagent를 띄울 수 있는지 Codex harness 기준 문서에 없음. → 대책: 중첩을 전제한 다단계 역할 체인을 설계하지 않음.
이번 설명에서 확인하지 않은 것 (Not Checked) & 제외 범위
  • Codex 실제 런타임에서의 Subagent 스폰 실측 (현재 Codex 세션 미연동 상태로, #110 마일스톤 실측 이슈에서 검증 예정)
  • Agent 본문(developer_instructions)의 상세 프롬프트 작성 (이번 #104 이슈의 명시적 제외 범위)
  • Hook을 통한 권한 강제 로직 (별도 후속 설계)
