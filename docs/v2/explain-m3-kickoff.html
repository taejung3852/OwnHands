💡 스스로 풀어보는 3초 퀴즈
Q1. spec.md가 이미 있는데 왜 plan.md가 별도로 필요한가요? 정답 확인
👉 spec.md는 "기술적 무엇(What)"을 정의하고, plan.md는 현재 코드베이스에서 "어떤 파일들을 어떤 순서로 수정할지(How)" 구체적인 실행 단계와 검증 계획을 고정하기 때문입니다.
Q2. 에이전트가 혼자 코드를 짜고 스스로 "다 됐다"고 착각하는 것을 막는 M3의 장치는? 정답 확인
👉 코드를 작성하기 전 테스트 실패를 먼저 확인하는 TDD 루프와, 구현자 맥락과 격리된 독립 검증자(verifier, read-only)의 객관적 대조 검증입니다.
🛠️ 엔지니어링 세부 사항 및 원문 근거 (Detailed Context)
  • 생략한 조건: Codex의 Plan mode나 비대화형 실행 인터페이스는 공식 조사(Step ①)를 통해 정확한 지원 여부와 작성 가이드를 확인한 뒤 연계 범위를 좁힙니다.
  • 주의할 예외: 특정 IDE/호스트의 내장 Plan Mode를 썼다고 해서 저장소의 plan.md 저장과 사람 검토가 자동으로 끝나는 것은 아니며, 별도의 Git 아티팩트로 보존되어야 합니다.
