PR #124 리뷰 대기 • 상태: Proposed

ADR-0007 확정 전
태정 님이 검토할 3가지 핵심

미승인 상태인 plan.md 규격을 정식 승인하기 위한 엔지니어링 체크포인트

1

plan.md를 Git에 영구 보존할 것인가?

Codex의 /plan 모드는 세션이 끝나면 사라집니다. 구현 변경의 이유와 단위 검증 내역을 프로젝트의 영구 Git 이력으로 남길지 결정합니다.

intent.md
의도 (Why)
➔
spec.md
설계 (What)
➔
plan.md
실행 계획 (How)
➔
Code / Commit
동작 검증
💡 태정 님의 확인 사항: docs/v2/specs/<feature>/plan.md에 영구 저장하여 "의도 ➔ 설계 ➔ 실행 ➔ 검증"의 3단계 감사 체인을 구축하는 것에 동의하십니까?
2

TDD는 '모든 작업 강제'인가, '적합한 로직에만'인가?

상위 계약은 스펙(spec.md)의 AC입니다. config, 문서, 권한, UI, 린트 같은 작업에까지 "실패하는 테스트"를 억지로 강제하지 않고 적절한 전략을 허용할 것인지 확인합니다.

❌ 기각된 방식 (과경직성) 모든 Task를 무조건 Red-Green TDD로 고정. 린트/UI/설정에 억지 테스트 래퍼 양산.
✅ 채택된 방식 (위계 & 유연성) SDD > Strategy > TDD.
로직/API는 TDD, UI는 렌더링 확인, 설정/문서는 정적 검사 수행.
💡 태정 님의 확인 사항: AC 1개당 테스트 1개 강제를 배제하고, Task 성격에 따라 단위테스트 / 정적분석 / 벤치마크 / 수동 점검을 유연하게 매핑하는 규칙에 동의하십니까?
3

Fresh Evidence의 범위와 Verifier의 경계

신선한 증거는 "터미널 명령"에만 갇히지 않으며, read-only 권한의 Verifier는 직접 테스트를 돌리기보다 독립 맥락에서 AC와 증거를 역추적 대조하는 역할로 한정합니다.

🔨 Builder Agent
구현 + 신선한 증거 생성
➔
🛡️ Verifier Subagent
read-only 역추적 대조
판정: PASS / FAIL / UNOBSERVED (테스트 재실행 권한은 M4에서 실측)
💡 태정 님의 확인 사항: Fresh Evidence를 "직접 관측된 최신 증거(테스트 출력, 스크린샷, 린트 결과 등)"로 넓히고, Verifier는 증거 재실행자가 아닌 독립 대조자로 두는 경계에 동의하십니까?
⚡ 3초 자가 점검 퀴즈
Q1. plan.md의 모든 Task는 '실패하는 테스트(Red)'를 반드시 포함해야 할까? 정답 확인
정답: 아닙니다 (X).
API나 비즈니스 로직에는 TDD(Red-Green)가 필수적이지만, 환경설정, 문서, 린트, 권한 검사, UI 렌더링 같은 Task는 해당 성격에 맞는 Verification Strategy(정적 분석, 빌드 확인, 렌더링 관측 등)를 유연하게 적용합니다.
Q2. Fresh Evidence의 핵심 요건은 '터미널 콘솔 출력'인가? 정답 확인
정답: 아닙니다 (X).
터미널 여부가 핵심이 아니라 "현재 변경에 대해 직접 관측했고, 과거 로그를 재탕하지 않은 신선한 증거이며, AC의 통과를 실제로 입증하는가"가 핵심입니다. 브라우저 스크린샷, 린트 무에러 출력, 벤치마크 수치도 모두 유효한 Evidence입니다.
🔍 핸드오프 검수 배경 및 엔지니어링 정합화 내역
  • Blocker 1 (승격 상태 정합화): 사용자 최종 확인 전에는 ADR-0007을 Accepted가 아닌 Proposed로 유지하며, decisions.md의 확정 표 반영을 보류합니다.
  • Blocker 2 (TDD 템플릿 강제 해소): plan.md 템플릿의 Task 정의를 "작은 변경 단위 ➔ 해당 Task에 적합한 Verification 수행 ➔ Evidence 확인"으로 일반화하고, TDD는 전략이 단위테스트인 Task에만 한정 적용합니다.
  • Blocker 3 (Fresh Evidence 정의 복원): PR #122의 합의에 맞춰 터미널 로그로 축소된 표현을 관측 가능한 직접 증거(Fresh Evidence) 전반으로 복원합니다.
  • Important (Verifier 권한 경계): verifier.toml의 sandbox_mode = "read-only" 특성상 명령 실행이 제한되므로, M3에서는 "증거 생성은 Builder, 독립 역추적 대조는 Verifier"로 경계를 정의하고 재실행 권한은 M4 실측 과제로 넘깁니다.
