## V1이 만든 것

V1은 "AI가 만든 작업이 정말 요구를 만족했는가"를 **구조로** 풀려고 했다.

```text
Issue → Verification Spec → Baseline → Review → Decision
                                ↓
                            Evidence
                                ↓
                           Dashboard
```

### 구현 코드

| 위치 | 내용 |
|---|---|
| `src/devharness/lifecycle/` | Issue·Spec·Baseline·Review·Decision 연결 계약 |
| `src/devharness/dashboard/` | Read-only 현황판 (View Model, Presentation, HTTP API) |
| `src/devharness/dashboard/web/` | HTML/CSS/JavaScript UI |
| `src/devharness/mcp/` | MCP 서버와 도구 |
| `tests/` | 검증 코드 |

> **UI 기술 참고**: V1 Dashboard UI는 **HTML/CSS/JavaScript**로 구현했다. React가 아니다.

### Skills

| 위치 | Skill |
|---|---|
| `skills/` | `using-ownhands` (라우터), `work-map`, `verification-spec`, `baseline`, `review`, `dashboard` |
| `legacy/skills/` | `context-validation`, `execution-control`, `harness-profiler`, `test-assurance` |

> ✅ **V2 방향**: `using-ownhands`를 포함한 기존 Skills는 V1/Legacy 관점으로 보고 V2에서 다시 설계한다.
> ⚠️ 문서에 `Legacy`라고 적었다는 이유로 **실행 경로까지 비활성화된 것은 아니다.**
> 실제 비활성화·이동·삭제는 별도 전환 작업이며 이번 문서 작업에 포함되지 않았다.

### 상태 어휘

V1이 정립한 상태 구분은 V2에서도 의미가 있다.

```text
Claim:      verified / failed / inconclusive / unobserved
Review:     ready / needs-review / blocked
Freshness:  current / stale / unknown
```

**`unobserved`와 `unknown`이 1급 상태로 존재한다는 점**이 이 프로젝트의 성격을 보여준다.

## V1 실행 방법 (과거 기록)

> ⚠️ **아래는 V1 기록이다. V2의 설치·실행 방법이 아니다.**
> V2는 아직 실행 가능한 제품이 없다.

```bash
PYTHONPATH=src uv run --python 3.12 python -m unittest discover -s tests -v
```

```bash
PYTHONPATH=src uv run --python 3.12 python -m devharness m1-demo \
  --data-root /tmp/devharness-m1-evidence \
  --output /tmp/devharness-m1-review.html
```

Python 3.12와 표준 라이브러리만 사용한다. Raw Evidence는 지정한 OS user-data 경계에 남고, HTML과 JSON report에는 Evidence ID·hash·scope·판정만 포함된다.

## 과거 실행 근거를 다루는 방법

V1 기록에는 전체 **579 tests**, **mutation 9/9** 같은 과거 보고가 있다.

| 이것은 | 이것이 아니다 |
|---|---|
| 당시 실행 근거 | V2의 완료 근거 |
| 출발점 | 현재 수용 검증의 실행 결과 |

> 이슈 #99 본문도 같은 기준을 적는다: "이전 기록의 전체 579 tests / mutation 9/9는 출발점이지 이번 수용 검증의 실행 결과가 아니다."

**테스트 수, Evidence 등록, 과거 PR, 체크박스만으로 완료를 주장하지 않는다.** 이것은 V1 때부터 이 프로젝트가 지켜온 원칙이다.
