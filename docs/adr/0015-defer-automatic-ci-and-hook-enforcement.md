# ADR-0015: 기존 자동 CI·Hook/Gate를 걷어내고 재설계를 후순위로 둔다

- 상태: 사용자 제거·우선순위 방향 확정 — 실제 제거 미진행
- 일자: 2026-09-22
- 관련: [#154](https://github.com/taejung3852/OwnHands/issues/154), 피드백 11·12와 이후 사용자 결정
- 조정 대상: [ADR-0010](0010-review-human-ci-governance.md)

## Context

사용자는 현재 Hook의 역할을 이해하기 어려웠고, 별도 review를 생략하고 push/PR을 요청했을 때 기대한 차단이 없었다고 보고했다. 당시 호출 경로·Hook 신뢰 상태·Evidence 상태의 원인은 확정되지 않았다.

사용자는 원인 조사보다 Chat 기획·설계, Build 인계, 단일 검증 구성을 우선하겠다고 명시했다. 따라서 Hook 원인 분석을 다음 작업의 필수 선행 조건으로 다시 올리지 않는다.

## 사용자 확정 방향

1. 기존 OwnHands의 자동 CI·Hook 강제 장치와 관련 Gate를 걷어내는 방향으로 한다.
2. 미차단 원인 조사와 새로운 CI·Hook 설계는 다른 우선 구성이 갖춰진 뒤에 다시 판단한다.
3. 제품 테스트, 독립 Verifier, 실제 실행 근거, 명시적 사람 승인은 유지한다. 자동 강제 장치의 제거를 무검증·무승인 작업 허용으로 해석하지 않는다.
4. 기존 구현과 관측 이력은 Git 이력에 보존한다. 과거 Hook 미관측이나 실패 경험을 PASS로 다시 쓰지 않는다.

## 후속 제거 작업의 경계

- Hook 파일뿐 아니라 관련 스크립트, Skill의 필수 Gate 안내, init 설치 및 doctor 진단 의존성, 문서의 자동 차단 주장을 함께 정렬해야 한다.
- 타 프로젝트·사용자가 원래 설정한 Hook이나 CI를 통째로 삭제하지 않는다. OwnHands가 소유한 자산과 병합 entry만 분리한다.
- 본래 제품의 test/lint/build와 기존 Evidence 기록을 자동 CI 제거의 부산물로 삭제하지 않는다.
- Evals 자산의 존재 자체를 곧 CI 강제와 동일시하지 않는다. 구체적으로 제거할 파일·참조는 후속 계획에서 확정한다.
- 자동 장치를 제거한 뒤에는 대화상의 승인 규칙을 강제된 보안 장치라고 표현하지 않는다.

## 고려한 대안

- 현 Hook을 즉시 더 강화: 사용자가 정한 우선순위와 다르고 기존 복잡도를 더 늘릴 수 있다.
- 진단부터 완료하고 다음 구조로 이동: 사용자가 명시적으로 보류한 경로다.
- 현 장치를 제거하고 핵심 흐름부터 재구성: 선택한 방향. 그동안 자동 차단의 보호가 없다는 한계는 표시해야 한다.

## 현재 이 커밋에서 한 것과 하지 않은 것

이 문서는 방향만 기록한다. `.codex/hooks.json`, Review Gate 스크립트, CI 설정, 설치기 또는 사용 프로젝트 파일을 실제로 삭제·수정하지 않았다. 삭제·마이그레이션 작업과 새 강제 장치의 검증은 완료되지 않았다.
