# ADR-0012: OwnHands MCP는 Intent·Spec·ADR 작성 Skill을 제공한다

- 상태: 사용자 방향 확정 — 기술적 전달 방식·Plugin 배포 상세 미결정
- 일자: 2026-09-22
- 관련: [#154](https://github.com/taejung3852/OwnHands/issues/154), 피드백 9-2와 후속 역할 정정
- 선행: [ADR-0011](0011-chat-codex-ownership-and-handoff.md)

## Context

기존 논의에서 OwnHands 전용 MCP를 GitHub 저장 기능의 중복으로 해석한 적이 있다. 사용자는 그 해석을 정정했다. 만들고 싶은 서버의 목적은 Git 파일 API 재구현이 아니라, ChatGPT에서 가이드라인에 맞춰 Intent·Spec·ADR을 작성하게 하는 Skill 제공이다.

GitHub의 파일 쓰기 도구가 있다는 사실만으로 GORE 인터뷰·설계 작성·ADR 판단 방법까지 제공되는 것은 아니다.

## 사용자 확정 방향

| 구성 | 책임 | 책임이 아닌 것 |
|---|---|---|
| OwnHands 작성 Skill | GORE 인터뷰, 모호성 해소, 문서별 작성 기준, 단계·승인 방법 | GitHub API 자체 구현 |
| OwnHands MCP/Plugin | ChatGPT가 위 Skill·가이드라인을 사용할 수 있도록 제공 | 별도 자율 기획 모델을 중복 운영 |
| GitHub 연결 도구 | 저장소·브랜치·파일 조회, 승인 문서의 커밋·저장 | OwnHands 작성 방법론의 대체 |
| ChatGPT | 제공된 작성 Skill을 적용해 사용자와 기획·설계 논의 | 승인 없는 구현·외부 변경 |

Mac Mini를 작성 Skill 제공 서버의 실행 환경으로 활용하려는 방향을 보존한다. Git 저장은 기존 쓰기 가능한 GitHub 도구와 분리한다.

## 기술 검증이 필요한 부분

다음은 방향과 별개로 아직 구현 성공을 확인하지 않은 사항이다.

- 개발자 모드/Plugin에서 Skill을 전달·등록하는 실제 지원 방식.
- MCP로 문서 내용을 읽는 것과 호스트에 네이티브 Skill로 등록하는 것의 차이.
- 로컬 서버와 ChatGPT 웹 사이의 접속·인증·권한 및 서버 중단 시 처리.
- Skill 원본 위치, 배포 버전, 갱신·캐시·스냅샷의 동작.
- 현재 연결된 GitHub 도구의 branch 쓰기 권한과 해당 작업의 사용자 승인.

단순히 MCP endpoint가 존재하거나 SKILL.md를 반환했다는 사실로 네이티브 Skill 로드가 관측됐다고 주장하지 않는다. 공식 지원 방식은 후속 구현 시 확인하고, 확인한 플랫폼 사양과 OwnHands의 선택을 구분한다.

## 대안과 결정

- GitHub 도구만 사용: 문서 저장은 가능하지만 작성 규칙 제공이라는 요구를 충족하지 못한다.
- 매 세션 긴 지침을 복사: 규칙의 재사용·일관성 관리가 어렵다는 사용자 문제를 남긴다.
- OwnHands Skill 제공 + GitHub 저장 도구: 선택한 역할 분담. 서버를 GitHub 기능의 중복이라는 이유로 없애지 않는다.

## 경계

이 ADR은 서버·Plugin 설치나 실행을 완료한 기록이 아니다. 새 MCP에 임의 Shell·전체 디스크·비밀 읽기를 기본 제공하지 않는다. 문서 저장 기능을 추가해야 한다면 기존 Git 도구와의 중복 이유 및 권한을 별도로 정한다.

## 후속 수용 확인 제안

작성 Skill이 실제로 제공·읽혔는지, 인터뷰와 세 문서의 목적이 구분되는지, GitHub 도구로 지정 브랜치에 승인 내용만 저장됐는지를 작은 한 사례에서 확인한다. 단순 endpoint 연결만으로 전체 흐름을 PASS 처리하지 않는다.
