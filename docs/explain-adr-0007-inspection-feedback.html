회귀 검증의 한계 & 기존 테스트의 지위

❌ 철학 충돌 & 과경직성
"전체 테스트 통과 = 0 회귀 증명" (과장)
"기존 테스트 불변" (정상 스펙 변경 차단)
✅ 엄밀한 엔지니어링 계약
"실행 범위 내 실패 미관측" (정확)
Baseline, not immutable (스펙 변경 시 갱신)
⚡ 3초 퀴즈
Q1. 전체 테스트가 다 통과하면 시스템에 회귀(결함)가 0건이라고 증명된 것일까? 정답 확인
A: 절대 아닙니다. 테스팅은 결함의 존재를 보일 뿐 결함의 부재를 증명하지 못합니다. "실행된 테스트 스위트 내에서 실패가 관측되지 않았다"가 정직하고 엄밀한 사실입니다.
Q2. 기존 테스트 코드는 절대로 수정하거나 건드리면 안 될까? 정답 확인
A: 아닙니다. 승인된 스펙 변경으로 API나 반환 규격이 바뀌면 기존 테스트도 정상 갱신되어야 합니다. 금지하는 것은 "실패를 숨기기 위한 무승인 테스트 약화/삭제"입니다.
