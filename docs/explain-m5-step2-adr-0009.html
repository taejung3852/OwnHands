ADR-0009 Proposed · 사용자 검토 대기

Continuous Evals Task Set과 경량 러너는 어떻게 회귀를 막는가?

정적/런타임 2계층 스키마와 3-State Delta Matrix 기반의 경량 회귀 감지 아키텍처 제안

1
선언형 Task Set 규격: static / runtime / composite 완전 수용
정적 파일 점검과 실제 에이전트 행동 관측 및 부작용 격리를 명확히 분리합니다.

전체 점수에 묻히는 결함을 막고, 이전 기준선 대비 상태 전이를 1:1로 추적합니다.

⚡ 스스로 풀어보는 3초 퀴즈
Q1. 5개 과제 중 4개가 통과하여 통과율이 80%라면 무조건 안전한 것인가? 정답 확인
💡 아닙니다! 만약 실패한 1건이 핵심 안전장치(read-only 불변성 등)라면 통과율 80%는 위험을 가리는 착시가 됩니다. ADR-0009는 개별 과제의 상태 전이를 핀포인트로 감지하는 3-State Delta Matrix를 제안합니다.
Q2. Codex CLI에 generic --dry-run 플래그가 공식으로 존재하는가? 정답 확인
💡 존재하지 않습니다! 공식 기능은 read-only sandbox이며, 외부 이슈/PR 생성을 막는 Dry-run 환경은 OwnHands가 스크립트 레벨에서 모킹·격리하는 자체 평가 환경입니다 (AGENTS.md 준수).
🛠️ ADR-0009 엔지니어링 투명성 및 결정 의제

3대 핵심 제안 요약:

  • Task Set 규격: docs/evals/task-set.yaml 단일 파일에 M1-M4 5대 과제를 execution_mode(static/runtime/composite) 및 sandbox_mode(read-only/isolated-write)로 완전 수용.
  • 러너 아키텍처: scripts/run-evals.js를 Eval Orchestrator로 삼아 빠른 정적 사전 검사(Preflight)와 Codex headless 런타임 실행을 2단계로 연계.
  • 회귀 지표: 단순 합격률 환치를 거부하고 docs/evals/baselines/current.json 기준선과 대조하는 3-State Delta Matrix 제안 (승인 시 확정).
