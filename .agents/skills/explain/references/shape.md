# Shape of an ELI5 Explanation

## The Test (10초 법칙)
독자가 글을 읽지 않고도 **큼직한 그림/다이어그램 2~3장을 훑어보는 것만으로 메커니즘을 즉시 이해**해야 한다.

---

## 핵심 원칙 (Core Rules)

1. **서술식 문장 전면 금지 (No Narrative Prose)**:
   - "~합니다", "~하기 위함입니다", "~에 해당합니다" 등 설명형 줄글 문장 일체 작성 금지.
   - 오직 **명사형 라벨, 핵심 키워드, 상태 뱃지, 수치, 대비(VS) 칩**으로만 표기한다.
2. **시각 요소 극대화 (Visual Dominance 80%+)**:
   - 카드의 면적 대부분은 **큼직한 다이어그램, 컴포넌트 박스, 굵은 화살표, 흐름 노드**가 차지해야 한다.
   - 텍스트는 시각 노드의 라벨 및 카드의 굵은 핵심 타이틀(1줄)로 한정한다.
3. **전문 용어 유지**:
   - 유아용 언어("도우미", "친구들")로 바꾸지 않고 정확한 엔지니어링 도메인 용어(`Subagent`, `read-only`, `AC`, `TDD`)를 그대로 큰 뱃지와 라벨로 배치한다.

---

## 레이아웃 구조 (위에서 아래로)

### 1. 호기심 헤더 (Curiosity Header)
- **질문 (H1)**: 핵심 메커니즘 질문 (예: "Subagent 3종은 어떻게 나뉘었나?")
- **상태 뱃지**: 현재 상태 태그 (예: `Accepted`, `Proposed`, `M3 진행 중`)
- **한 줄 요약**: 서술문이 아닌 명사형 핵심 메커니즘 1줄 (15자 내외).

### 2. 단계별 시각 카드 (Big Visual Cards, 2~3장)
- **헤더**: 번호 뱃지(`1`, `2`, `3`) + 굵은 핵심 타이틀 1줄.
- **중앙 대형 시각 컴포넌트 (핵심)**:
  - 거대한 파이프라인 노드 (`Node A ➔ Node B ➔ Node C`)
  - 채택 vs 기각 대비 박스 (`❌ 기각 이유` vs `✅ 채택 방식`)
  - 권한 뱃지 (`read-only`, `sandbox`, `PASS / FAIL`)
- **텍스트 한도**: 카드 1장당 설명 텍스트는 라벨/태그 형태 1~2개로 제한. 서술식 설명 단락 절대 금지.

### 3. 스스로 풀어보는 3초 퀴즈 (Interactive Quiz)
- 눈으로 본 시각 구조를 즉시 점검하는 직관적 퀴즈 1~2개.
- **반드시 `<details class="quiz-item">`과 `<summary>`로 정답 기본 숨김**.

### 4. 접힌 기술 세부 사항 (`<details>`)
- 생략한 전제, 예외, 원본 아티팩트 링크(PR, Issue, ADR)는 하단 접기 블록에만 보관.
